# Carbon Actual Economic, Ledger and Tokenization Boundary

Status: canonical technical contract beneath the economic ontology.

## Separation

```text
IO       = movement / access / exchange / flow
Pulse    = activity feedback / evidence
Value    = evaluated contribution / outcome / economic measurement
Ledger   = durable accounting / ownership / custody / provenance record
Settlement = external or internal mechanism that fulfills an obligation
Token    = representation of a qualified object/right/value
```

None of these concepts silently becomes another.

## Logical ledgers

Implementations may maintain logical ledger families for identity, authority/consent, activity, value, ownership, custody, provenance, relationships, contracts, resources, capability, reputation/evidence, security, governance and continuity.

A ledger can use relational persistence, append-oriented storage, distributed ledgers or blockchain according to context. Blockchain is not a constitutional requirement.

## Economic boundary

The runtime follows:

```text
RESOURCE/CAPACITY
  -> ACTIVITY
  -> PULSE
  -> EVALUATION
  -> VALUE/OUTCOME
  -> ACCOUNTING
  -> EXCHANGE/PROVISION
  -> NEXT STATE
```

Pulse is never automatically treated as currency, permission or authority. Exact value-differential formulas remain empirical and jurisdiction-aware.

## Tokenization boundary

```text
canonical object/right/value
  -> qualification
  -> token representation
  -> ownership/custody
  -> transfer/settlement
  -> provenance
  -> state/revocation/recovery
```

The underlying governed object or right remains primary. Token state cannot manufacture ownership or authority that does not exist in the canonical record.

## Anti-duplication rule

A financial product may add domain workflows, products, interfaces and settlement adapters, but may not create a second economic constitution, universal ledger ontology or independent authority system.
