# Carbon Actual ABBA / Swarm / Team / Workflow Boundary

Status: canonical technical contract beneath the frozen Carbon Actual architecture.

## Runtime lifecycle

```text
INTENT / EVENT
  -> CONTEXT
  -> CAPABILITY DISCOVERY
  -> SWARM EVALUATION
  -> TEAM COMPOSITION
  -> WORKFLOW
  -> IDENTITY + AUTHORITY + POLICY + CAPABILITY GATES
  -> EXECUTION
  -> OBSERVATION / EVIDENCE
  -> PULSE
  -> VALUE / OUTCOME
  -> LEARNING / CURATION / BECOMING
```

## ABBA

ABBA is the ecosystem master intelligence/orchestration intelligence. ABBA may interpret context, discover capability, evaluate alternatives, compose teams, plan workflows and route execution, but intelligence itself is not authority.

## Swarm

A Swarm represents the comparative capability field available to a context. It may evaluate capability quality, evidence, health, availability, risk, cost/value and suitability.

## Team

A Team is a contextual composition selected from the capability field. Teams can change as evidence or conditions change. Team membership does not grant new authority.

## Workflow

A workflow coordinates selected capabilities and actors. It records intended transitions and execution dependencies; it is not a constitutional layer.

## Mandatory gates

Consequential execution must separately evaluate:

```text
identity
+ authority/delegation
+ applicable policy
+ capability suitability
+ resource/dependency readiness
+ risk/safety conditions
```

Matching and interpretation are upstream signals, not authorization.

## Mission/readiness

Existing mission-intelligence and readiness engines remain the authoritative pre-execution implementation where already established. New orchestration code should bind to those contracts rather than create a competing readiness system.

## Recomposition

Recomposition is permitted when capability availability, safety, context, human availability, authority scope or risk changes. Every recomposition must preserve evidence and authorization lineage.
