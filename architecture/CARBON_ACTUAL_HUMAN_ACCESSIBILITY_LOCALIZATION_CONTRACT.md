# Carbon Actual Human Accessibility & Localization Contract

**Status:** CANONICAL CROSS-CUTTING CAPABILITY CONTRACT  
**Authority:** HAPI World `CANON.md` + Carbon Actual operating-spine contracts

## Purpose

Every Carbon Actual product, institutional deployment and communication surface must be able to adapt to human differences in language, locale, literacy, disability, connectivity, device, input method and presentation preference without changing canonical meaning.

Accessibility and localization are composition capabilities, not product-specific afterthoughts.

## Boundary

This contract does not create:
- a second identity model;
- a second policy model;
- a second content ontology;
- a second UI architecture;
- a separate accessibility constitution.

Canonical meaning remains independent from presentation.

`canonical meaning → localized representation → accessible interaction → human feedback`

## Accessibility dimensions

Implementations should support, where applicable:
- visual alternatives for non-text content;
- keyboard and non-pointer interaction;
- screen-reader semantics;
- captions and transcripts;
- audio alternatives;
- sign-language interfaces where applicable;
- adaptable text size and presentation;
- sufficient interaction targets;
- reduced-motion preferences;
- color-independent meaning;
- high-contrast modes;
- readable language and content structure;
- error identification and recovery;
- assistive technology interoperability;
- low-bandwidth and offline-friendly interaction;
- voice and alternative input;
- haptic/tactile interaction where useful.

Accessibility requirements are part of capability/context and must not alter the canonical object, event, evidence or authority semantics.

## Localization

Localization may vary:
- language;
- script;
- numbering and decimal conventions;
- date/time presentation;
- calendar presentation where appropriate;
- units and measurements;
- currency presentation;
- address and territory formatting;
- timezone;
- local terminology;
- reading direction;
- legal/regulatory notices;
- cultural presentation.

Localization must never silently alter a transaction amount, legal obligation, identity, authority, date meaning or settlement semantics. Canonical values remain stored in unambiguous machine-readable form with explicit units, locale and timezone context.

## Internationalization

Canonical objects should be locale-neutral wherever possible.

Text, labels and presentation resources should be separable from semantic records. Translation and localization metadata remain provenance-bearing where material meaning may change.

A translation is a representation, not a replacement for the source record.

## Language and AI

AI may translate, summarize or adapt language, but:
- generated translation remains derived output until validated where material;
- uncertainty must be preserved;
- translated legal/financial/medical instructions may require qualified review;
- AI language adaptation cannot enlarge authority or consent;
- user language preference cannot be inferred as permission to expose private content.

## Accessibility and consequential actions

For consequential flows, accessibility must include an equivalent path to:
- inspect relevant information;
- understand authority and commitments;
- confirm or decline;
- review evidence;
- access recovery;
- export/exit.

No user should be required to bypass an accessibility layer to reach a consequential action.

## Product composition

Products consume this contract.

A product may specialize:
- terminology;
- local forms;
- interaction patterns;
- assistive presentation;
- locale-specific workflows.

It must preserve the same canonical semantics underneath.

## Testing and evidence

A mature product should test applicable accessibility and localization paths across:
- primary supported languages/locales;
- assistive technologies;
- keyboard/voice/alternative input;
- low-bandwidth conditions;
- responsive/mobile/desktop layouts;
- right-to-left presentation where applicable;
- localized dates, numbers, units and currencies.

Failures become observable evidence and should feed the product's correction/recovery path.

## Invariants

1. Accessibility changes interaction, not canonical meaning.
2. Localization changes representation, not canonical semantics.
3. Translation is not silent data mutation.
4. Locale is not authority.
5. Language preference is not consent.
6. Accessibility preference is not a new identity.
7. Human-readable values must retain unambiguous canonical machine values.
8. No consequential path may become inaccessible merely because a user needs an alternative interface.
