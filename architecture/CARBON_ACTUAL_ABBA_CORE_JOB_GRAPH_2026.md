# Carbon Actual — ABBA Core Master-Intelligence Job Graph

ABBA is the Master Intelligence and Orchestrator of the ecosystem. The HAPI World Canon remains the constitutional authority; ABBA interprets, composes, routes, proposes, coordinates, and learns within that authority boundary.

## Operating sequence

`Signal → Authenticate → Validate → Classify → Correlate → Preserve contradictions → Detect anomaly → Synthesize → Identify objective → Discover capabilities → Assess readiness → Swarm → Team → Minimum-context routing → Workflow/Mission → Authority/Policy Gate → Authorization → Execution → Evidence → Event/State reconciliation → Value/Pulse reconciliation → Learning → Maintenance/Recovery → Continue/Stop`

This sequence deliberately separates observation, reasoning, composition, authorization, execution, evidence, reconciliation, and continuation. No earlier stage silently performs the work of a later stage.

## ABBA's core jobs

ABBA is responsible for more than team formation. It continuously operates as the ecosystem's reasoning, orchestration, stewardship, and completion engine:

- Understand what exists, what changed, what is requested, what is missing, and what is anomalous.
- Discover and compare available capabilities before composing a response.
- Form Swarms for comparative capability discovery and Teams for contextual execution.
- Route only the minimum context required for each task.
- Build workflows and missions from objectives and dependencies.
- Preflight policy, authority, risk, consent, resources, evidence requirements, and idempotency.
- Request authorization when authority is absent or insufficient.
- Coordinate execution without manufacturing authority.
- Capture evidence and reconcile event, state, Value, Pulse, ledger, and settlement outcomes.
- Learn from validated outcomes and preserve contradictory observations instead of erasing them.
- Detect drift, duplication, waste, dead paths, bottlenecks, failures, and incomplete work.
- Repair and recover through governed proposals.
- Continue automatically when the next job is clearly eligible and safe; stop explicitly when a terminal condition is reached.
- Produce traceable summaries explaining what was observed, inferred, proposed, executed, verified, and left pending.

## The completion rule

An ABBA mission does not end merely because one action finished. It ends when the objective is complete, the remaining work is explicitly blocked, or a terminal condition is reached and recorded.

Continuation can create new jobs, but every newly created consequential job re-enters the same governed sequence. This prevents recursive autonomy from becoming self-authorization.

## Design boundary

Telemetry is an observation input, not canonical truth. Team selection is a proposal, not authority. Execution is a separate gated stage. Canonical events remain the durable record of consequential state transitions, while observations and proposals remain separately identifiable layers.

## Current implementation boundary

Phase 2 implements the governed observation-to-proposal runtime and durable observation/proposal storage interfaces. Execution and authorization remain intentionally behind the existing Carbon Actual authority boundary.
